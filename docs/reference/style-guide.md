# Documentation style guide

This short guide is a place to test Vale and learn how style rules complement human editing.

## Write for action

Start a procedure with a verb and explain the outcome. Prefer "Create an environment" to "Environment creation."

## Use precise, respectful terms

Use `allowlist` instead of `whitelist` and `blocklist` instead of `blacklist`. The included Vale rule marks those older terms as suggestions.

## Do not minimize complexity

Avoid words such as "simply" and "obviously." They can make a necessary task feel like a reader's failure. Explain the action, prerequisites, and expected result instead.

## Treat Vale as feedback

Vale can catch repeatable wording and terminology issues. It cannot verify product behavior, replace a technical review, or decide whether a page is useful. Review the rule message and update the content only when it improves the sentence.
